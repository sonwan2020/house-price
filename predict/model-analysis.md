# Training model analysis

Analysis of the house-price regression over `data/House Price Dataset.csv`
(50 rows, 7 features). Companion to `README.md` ("Model selection") and
`models-train.md` (the no-`lot_size` variant).

## 1. Problem: negative coefficients are not explainable enough

Plain linear regression (OLS) on the full dataset produces coefficients
with counter-intuitive signs:

| coefficient | value |
|---|---|
| square_footage | **−103** $/sq ft |
| bedrooms | **−8,448** $/bedroom |

A user reading the model would conclude that a *bigger* house or an *extra
bedroom* lowers the price — the opposite of domain expectation. These
negative coefficients are not individually explainable, so the model
cannot be defended feature-by-feature.

## 2. VIF analysis: `square_footage` is the most redundant feature

Variance inflation factor (VIF) measures how predictable each feature is
from the other six (VIF > 10 is commonly flagged as problematic):

| feature | VIF |
|---|---|
| **square_footage** | **212.2** |
| lot_size | 149.8 |
| year_built | 87.9 |
| distance_to_city_center | 68.6 |
| school_rating | 49.0 |
| bathrooms | 23.8 |
| bedrooms | 13.7 |

`square_footage` is the most redundant of the 7 features: its VIF of 212
means the other six features explain ~99.5% of its variance. Its pairwise
correlations are 0.99 with `lot_size`, 0.99 with `year_built`, 0.99 with
`school_rating`, 0.98 with `distance_to_city_center`, 0.97 with
`bathrooms`, and 0.93 with `bedrooms` — it carries no independent
information.

## 3. Retraining the linear model without `square_footage`

Retraining plain OLS with `--drop-features square_footage` (6 features):

| coefficient | value |
|---|---|
| intercept | 3,639,459 |
| school_rating | 15,299 |
| distance_to_city_center | 12,055 |
| bathrooms | 10,963 |
| bedrooms | **−3,556** |
| year_built | **−1,895** |
| lot_size | 31 |

CV accuracy is unchanged — even slightly better (RMSE 9,793 → 9,211;
R² 0.982 → 0.984). But the sign problem did **not** go away: the negative
weight moved from `square_footage` onto `bedrooms` *and* `year_built`.
Removing the worst duplicate only redistributes the sign flip among the
remaining collinear features.

## 4. Root cause: the problem is introduced by the training dataset

The un-explainable coefficients are a property of the data, not of the
model choice:

- The dataset has only **50 rows**, and every feature correlates 0.91–0.99
  with every other feature — the data lies almost on a single axis
  (a "suburban premium" bundle where size, age, school quality and
  distance all move together).
- Under such collinearity, OLS splits one shared price effect arbitrarily
  across features: the individual coefficients are not identifiable, and
  any small perturbation of the data reshuffles them (as seen when
  dropping `square_footage`).
- Predictions remain accurate (CV R² ≈ 0.98) because the shared axis is
  strongly price-correlated, but the **per-feature coefficients are not
  explainable enough** — no retraining on this dataset can produce
  individually meaningful OLS coefficients.

To get an explainable model, the training dataset would need to be
regenerated with a realistic structure (more rows, features that vary
independently, e.g. central flats that are small and expensive while
suburban houses are large). Alternatively, the deployed `linear_positive`
model — trained without `square_footage`, the most redundant feature — is
the defensible compromise: non-negative least squares pushes the remaining
redundant features (`bedrooms`, `year_built`) to exactly zero instead of
letting them flip negative — honest feature selection under collinearity
rather than arbitrary signs.

## 5. Comparison: linear regression without `square_footage`

Generated by `scripts/compare_models.py` (linear runs trained with
`--drop-features square_footage`):

### Coefficients (original units)

|  | intercept | square_footage | bedrooms | bathrooms | year_built | lot_size | distance_to_city_center | school_rating |
|---|---|---|---|---|---|---|---|---|
| linear (all 7 features) | −299,787 | −103 | −8,448 | 7,437 | 112 | 39 | 16,810 | 21,062 |
| linear (without `square_footage`) | 3,639,459 | — | −3,556 | 10,963 | −1,895 | 31 | 12,055 | 15,299 |
| linear_positive (without `square_footage`) | −2,405 | — | 0 | 9,089 | 0 | 18 | 19,172 | 4,257 |

### CV metrics

|  | alpha | r2 | mae | rmse |
|---|---|---|---|---|
| linear (all 7 features) | — | 0.982 | 7,107 | 9,793 |
| linear (without `square_footage`) | — | 0.984 | 7,156 | 9,211 |
| linear_positive (without `square_footage`) | — | 0.985 | 7,537 | 9,216 |

Dropping `square_footage` costs nothing in accuracy and removes the worst
duplicate column — but plain OLS still ends up with negative coefficients
(`bedrooms` −3,556, `year_built` −1,895), while `linear_positive` keeps
every sign non-negative at the same accuracy, which is why it remains the
deployed default.
